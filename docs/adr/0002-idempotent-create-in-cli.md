# 冪等な Issue 作成を CLI に吸収する

> 作成日時: 2026-08-18 03:19
> 更新日時: 2026-08-18 03:19

Asana 連携時の重複 Issue 防止メカニズム（マーカー走査 → 既存なら再利用 / 無ければ作成 → 不確実なら再走査）を CLI 側の `issue create --dedupe-key` として実装し、スキル側の Bash ガードに依存しない。本文は呼び出し側が埋め込み、CLI は注入しない。作成前に本文中の構造化マーカー（前後空白を除いた 1 行が `Label: value`）がちょうど 1 回あることを検証し、欠落なら検証不一致で失敗する。既存 Issue の走査は Open / Closed を最終ページまで辿り、各 Issue の Raw Markdown を見る。ページ欠落や解析失敗は 0 件と見なさない。既存は 1 行以上で一致。不確実記録は POST 直前に書き、正規形の成功または整合のあとで消す / 遷移する。既存記録がある次の実行は、Override が無い限り POST しない。先に走査し、1 件なら再利用して記録を消し、0 件または走査失敗なら記録を残して終了コード 2、2 件以上なら終了コード 3。応答喪失時は同一プロセス内で即再走査し、1 件なら再利用として報告、0 件なら記録を残して不確実終了、2 件以上なら終了コード 3 とする。再走査も失敗したら記録を残して終了コード 2。作成後の確認走査も同じ件数契約に従う。不確実記録がある限り再作成しない。ロック取得失敗は待たずに終了コード 1 とし、専用コードは増やさない。`--override-uncertainty` が外すのはこの再作成禁止だけであり、走査 0 件なら POST、1 件なら再利用、2 件以上なら曖昧のまま失敗する。記録が無いときの指定は無視する。終了コード契約: 0=成功（再利用含む）/ 2=不確実・再実行で走査整合 / 3=曖昧・人手確認 / 4=認証失敗 / 5=検証不一致。
