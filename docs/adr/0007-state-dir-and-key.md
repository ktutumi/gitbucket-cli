# ロック・不確実記録は新規状態ディレクトリに置き、キーを曖昧でない直列化で定める

状態は `$HOME/.cache/gitbucket-cli/` に置く。キー = SHA-256(JSON 配列 `["正規化URL","owner","repo","marker-label","dedupe-key"]`)。URL 正規化 = scheme/host 小文字・既定ポート除去・末尾スラッシュ除去・空パスは `/`・クエリ/フラグメント除外。フィールド連結は曖昧で境界衝突する（`owner="ab",repo="c"` と `owner="a",repo="bc"`）ため、JSON 配列で直列化する。marker-label をキーに含めてラベル間のレコード衝突を防ぐ。スキルのキャッシュ形式には結合しない。移行中の競合（両者が同時に 0 件走査→双方 POST）は「wrapper を単一入口とし、同一 owner/repo/キーに対して旧スキルと `bkt` を同時実行しない」という明示シーケンス規則で閉じる。マーカー走査単独では競合窓を閉じない。
